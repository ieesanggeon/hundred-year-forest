# Windows 배치 실행기

## 사용 방법

1. 프로젝트의 `run_game.bat`을 더블 클릭한다. 폴더 안의 `index.html`, `dist/game.bundle.js`, 서버 파일을 함께 유지해야 한다.
2. 서버가 정상적으로 준비된 뒤 기본 브라우저를 연다. 기본 주소는 `http://127.0.0.1:8000`이다.
3. 다른 프로그램이 해당 포트를 점유했으면 다음 빈 포트를 사용한다. 실제 주소는 실행 창에 표시한다.
4. 브라우저가 자동으로 열리지 않으면 표시된 주소를 직접 연다. 서버를 종료하려면 실행 중인 배치 창에서 Ctrl+C를 누른다.

같은 폴더의 게임 서버가 이미 실행 중이면 그 서버를 재사용한다. 다른 프로그램이나 다른 게임 폴더의 서버를 잘못 열지 않도록 게임·폴더 식별 정보를 확인한다.

## 수정한 문제

- 기존 UTF-8 한글 배치파일의 줄바꿈이 LF였고, Windows 명령 해석기가 명령을 중간에서 잘라 실행하는 현상을 재현했다. 같은 내용을 CRLF로 바꾼 검사에서 정상적으로 Node.js 서버 실행까지 도달했다.
- 배치 명령을 ASCII로 작성하고 파일 줄바꿈을 Windows CRLF로 저장했다. `.gitattributes`에도 배치파일의 CRLF 보존 규칙을 추가했다. 게임 서버 안내는 Node.js에서 한국어로 출력한다.
- 현재 폴더와 관계없이 배치파일이 있는 게임 폴더에서 시작한다. 실행 파일과 경로를 따옴표로 감싸 공백·한글이 있는 경로도 처리한다.
- 검색 경로에서 Node.js를 찾지 못하면 일반 설치 위치도 확인한다. Node.js가 없으면 `py -3` 또는 실제 Python 실행 파일을 찾는다. Microsoft Store의 실행 별칭만 있는 경우는 실제 Python으로 선택하지 않는다.
- 서버가 켜지기 전에 브라우저를 열던 순서를 바꿨다. 포트를 확보한 다음 브라우저를 연다. 포트 충돌 시 빈 포트를 선택하고, 같은 게임이 이미 켜져 있으면 재사용한다.
- 게임 파일 누락·실행 실패 시 안내와 오류를 표시한 채 창을 유지한다. 최신 HTML·코드·음원에 `no-store`를 적용한다.

## 구현 파일

- `run_game.bat`: Windows 실행 파일 찾기, 작업 폴더, 오류 표시.
- `server.js`: Node.js 서버, 준비 확인, 포트 선택·중복 실행 처리와 브라우저 열기.
- `server.py`: Python 표준 라이브러리로 구현한 대체 서버.
- `tests/launcher.cjs`: 실제 Windows 배치 실행과 서버 검사.

## 검증

`npm run test:launcher`로 다음 항목을 확인했다.

| 항목 | 결과 |
| --- | --- |
| 배치파일의 ASCII 명령·CRLF 줄바꿈 | 통과 |
| 실제 cmd.exe에서 배치파일 실행 후 서버 응답 | 통과 |
| Node.js를 검색 경로에서 제외한 상태의 일반 설치 위치 탐색 | 통과 |
| 게임과 다른 현재 폴더에서 실행 | 통과 |
| 공백·한글이 들어간 폴더에서 실행 | 통과 |
| 기본 포트가 다른 프로그램에 점유된 상황 | 빈 포트 사용 |
| 같은 게임의 중복 실행 | 기존 서버 재사용 |
| HTML·번들·MP3 제공 | 통과 |
| 잘못된 URL·게임 폴더 밖 파일 요청 | 오류 응답 후 서버 유지 |
| 필수 게임 파일이 없는 폴더에서 실행 | 오류 안내와 실패 코드 |

이 컴퓨터에서는 설치된 Node.js를 사용해 검증했다. 검사 중 시작한 서버만 정리하며, 검사는 브라우저 자동 열기를 생략하는 `--no-open` 옵션을 사용한다. 별도로 실제 배치파일의 기본 실행과 브라우저 열기도 실행해 확인했다.
